# Mega-goal: kit-modularity

**Destination:** dwarves-kit becomes the MIDDLE-LEVEL composable toolkit (Han: a toolbox you install a-la-carte, NOT a monolithic product you adopt whole). Each subsystem is a self-contained, independently installable STANDALONE command (`board`, `stats`, `gate`, `session`, ...) with its own `<subsystem> <verb>` surface; the `lib/`-vs-`tools/` split is retired into per-subsystem modules; enablement is by shell install/wire per-module + a light `kit.toml [modules]` manifest (essential spine always wired, optional add-ons opt-in); the observability domain is an event-sourcing plane split , an append-only ledger (write, source of truth) + a `stats` projection engine (read, recomputable, renamed from `ledger-observatory`) over a configurable `KIT_LEDGER_DIR`; every important module ships a co-located usage doc AND a real workflow firing point (no orphans); and the operate-contract (`AGENTS.md`/`WORKFLOW.md`) + the three goal-scaffolding surfaces (`plan-for-goal`, `plan-for-mega-goal`, `/kit:mega`) are reconciled to the new surface.

**Quality bar:** Boring, composable, Unix-y. A consumer who wants ONLY the SDD spine installs it and NOTHING else gets wired , no heavy appliance feeling. Every standalone command works if you delete the optional `kit` dispatcher. A projection is NEVER a second source of truth (event-sourcing discipline: recompute from the ledger, never persist a derived ledger that drifts). Zero call-site breakage through the module collapse (kit-foldin's SG-01 resolver + additive entries). No module ships undocumented or unwired. The three scaffolders agree byte-for-byte where they mirror.

**Terminus:** non-deployable (structure + docs + contract reconciliation across dwarves-kit + the two scaffolding skills). Build + merge IS the terminus. The convergence gate: the full kit suite green on merged master; a spine-only install into a temp HOME wires ONLY the spine; each module has a doc + a named firing point; the three scaffolders pass the re-run mirror check. Deliberately no deploy/UAT (that is the separate Hermes-cockpit mega, decision H).

## Assumptions (from the kit-modularity design note, decisions A-G, 2026-07-05)

BINDING design: `research/2026-07-05-kit-modularity-design.md` (decisions A-G; H is a SEPARATE mega).

1. **Middle level, not a product** (rejected framing): standalone installable commands, NOT a `kit` uber-binary; the thin `kit` dispatcher is optional discovery-sugar.
2. **Type-first stays** (loader-mandated): `agents/`/`commands/`/`hooks/`/`skills/` top-level; module collapse only affects the non-loader tree (`lib/` + the retired `tools/`).
3. **Event-sourcing discipline** (E): append-only ledger = source of truth; `stats` = stateless projection; a derived ledger is a VIEW, never persisted as a 2nd source (the board-mirror drift class of bug).
4. **`stats` name** (Han's pick over obs/metrics/monitor/lens): read-side never carries `-ledger`. RUN_REPORT stays the mega flow's own closing verb, NOT a `stats` subcommand.
5. **One ledger root per consumer** (`KIT_LEDGER_DIR`, essential-tier, via `--repo-root`/`_repo_root()`); tests point it at mktemp; never per-stream-configurable.
6. **Enablement by install/wire** (B): a `[modules]` manifest RECORDS + tiers; it is not a runtime feature-registry every hook reads. Install wires only opted-in hooks.
7. **Module completeness bar** (F): usage doc + firing point per module, or not done. Reuses ID-273's firing-point audit.
8. **Reuses runner-fastpath patterns**: hand-made worktrees for kit sub-goals (NEVER Agent isolation:worktree); conductor-transcribes bookkeeping; OPERATE.md run contract; ship-gate proof-of-done; over-test behavioral sub-goals with NCs.
