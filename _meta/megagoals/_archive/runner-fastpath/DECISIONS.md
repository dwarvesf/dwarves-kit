- 2026-07-05 SG-08 (bridge-writeback) changeset format + Hermes-writeback semantics: NDJSON rows with `origin/repo/id/hermes_id/board/backlog_file/repo_root/current_status/target_status/hermes_status/row_hash`. The Hermes->git reverse mapping is DELIBERATELY LOSSY (this is a design choice, not a gap): `triage->queued`, `ready->claimed` (the single honest nearest state -- 07's forward mapping already collapsed `claimed/speccing/validated/executing` all into `ready`, so there is no way to recover which one a card WAS without guessing; `claimed` is the least-committal choice), `blocked->parked`, `done->shipped`; anything else (`todo`, `running`, or an unrecognized Hermes status) is REJECTED, never silently coerced. Writeback applies status-column edits via an ISOLATED `git worktree` branch (never the caller's own working checkout) so a concurrent conductor/human session editing the same repo is never disturbed mid-writeback. Snapshot refresh after a successful apply updates ONLY `hermes_status` in the snapshot, leaving `row_hash` untouched, because the sync PR is HELD (unmerged) at that point -- the git SoT hasn't actually changed yet, so bumping the hash would desync `board mirror`'s next idempotence check. Consequence (documented limitation, not a bug): if Han closes a board-sync PR WITHOUT merging it, writeback will not automatically self-heal on its own; it needs a fresh Hermes-side card move to re-trigger a changeset for that row. Rung-4 confirmed fail-closed against: stale-hash edits, 4 missing/corrupt-snapshot variants, 3 opted-in-filter bypasses, and a live backtick command-injection payload via a crafted `origin` field -- all blocked with zero code changes needed (the design held on first red-team pass).

- 2026-07-05 SG-07 (bridge-mirror) load-bearing discovery: the design doc's assumed 6-state git<->Hermes mapping does NOT hold under the real installed Hermes CLI (v0.18.0). `create --initial-status blocked` and `block --kind dependency` (the doc's plan for the `todo` state) both auto-promote back to `ready`/`todo` within ~15-20s with NO gateway process running -- verified live, multiple times, both a 3-row and a 20-row batch.
