## Architecture: the verification loop

```
/user:execute
  |
  v
Parse SPEC.md > present execution plan > human approves
  |
  v
For each phase:
  For each task:
    dispatch worker subagent (Task tool, fresh context)
      |
      v
    dispatch task-verifier (read-only subagent)
      |
      +-- PASS --> mark done, continue
      |
      +-- FAIL:fixable --> dispatch fix-agent
      |     |               re-run task-verifier
      |     +-- retry_count < 2? loop back
      |     +-- retry_count >= 2? escalate
      |
      +-- FAIL:escalate --> stop, ask human
  |
  v
Phase checkpoint (human gate)
```

## Known gotchas

- Path-scoped rules only work in project-level `.claude/rules/`, not `~/.claude/rules/`. Silent failure.
- Path-scoped rules only activate when Claude READS matching files, not on write/create.
- task-verifier and fix-agent require Claude Code's custom subagent support (`.claude/agents/` directory with YAML frontmatter). Available since Claude Code v2.0.60+.
- The retry loop is orchestrator logic inside the execute.md prompt, not enforced by a hook. Claude follows prompt instructions ~85% of the time. If it skips verification, the anti-rationalization Stop hook may catch the premature completion.
