## Problem

Core `lib/board` and `lib/sync` name four specific apps. `git grep -il hermes -- lib/board lib/sync` lists 26 files today, and 40 files name at least one of Hermes, Notion, Reminders or Multica. Adding or removing an app means editing the engine, the board dispatcher and the sweep scripts. A kit install that wants none of the four still ships all of them in core paths.

The goal (board row ID-937, full lane):

- Core `lib/board` and `lib/sync` have zero references to the four apps: `git grep -il hermes -- lib/board lib/sync` prints nothing, and the same for notion, reminders and multica. (The scan is over tracked files. Ignored `__pycache__` directories that an old checkout leaves behind are not part of the tree; see T1.)
- Each connector sits behind one adapter interface, and adapters load by config: `[sync] apps` names the adapters a repo runs, as it does today; the only new input is the directory the loader scans, set by one environment variable that tests and extensions use.
- All four adapters pass the existing sync tests through the interface.
- Doctrine this follows (`docs/decisions/0041-standalone-doctrine.md`): core names no specific app; connectors are adapters loaded by config; the kit's integration of a module is a thin shim. The ADR calls closing this gap "the next piece of work" and asks that it cite the ADR and answer its checks (answered under Design, ADR link).

The hard constraint, from the live callers below: this host runs the kit straight from the main checkout (`~/.claude/dwarves-kit` links `bin`, `lib`, `hooks`, `kit.toml` into it, and `/Users/Shared/dwarves-kit` links the same checkout for the neko-chief account). A merged move is live at once, with nobody to review it by hand. No installed launchd job and no cron entry point may change its path or its behavior, and the change must be provably a move plus an indirection: the same inputs make the same calls to the same stores and print the same output. TASK-A1 and TASK-A2 capture that proof before the first move and TASK-S diffs it after the last.

## Terms

- adapter: a directory `lib/adapters/<name>/` holding one connector: a manifest `adapter.tsv`, an entry module `adapter.py`, its own code and a README. Tests live in `lib/adapters/tests/`.
- manifest: `adapter.tsv`, tab separated rows that tell core which apps, flags, verbs, sweep legs and constants the adapter provides. Core reads manifests and never names an app. The adapter name is its directory name; the entry module is always `adapter.py`.
- app: a name usable in `[sync] apps` and `--apps` (`hermes`, `notion`, `notion-taskboard`, `notion-taskboard-pull`, `reminders`, `multica`, `github`). App names are frozen: they key `<app>.state.json`, the filter keys and the config keys.
- verb: a `board <verb>` word that an adapter provides (`mirror`, `status`, `writeback`, `mirror-cleanup`, `hermes`).
- leg: a script `board sweep` runs after the per-repo syncs (the Hermes mirror, the expiry and the link check).
- core: every tracked path under `lib/board/` and `lib/sync/`. After this spec no dated record sits there (see TASK-O), so the purity check has no exemption list.
- characterization: the golden capture of the fixture and stub output of every entry point, taken on the untouched tree (TASK-A1, TASK-A2) and diffed after each task and at the end (TASK-S).

## Solution

### Approaches considered

1. Subclass registry in Python only. A base class `Source` and a Python `register()` call per adapter. It covers the engine but not the bash side (`cmd_sync` flag lines, verbs, sweep legs, the Multica token), which is where most of the Hermes references live, so it would leave about half the grep hits.
2. Plain convention, no manifest: `verbs/<verb>` executables, `legs/<phase>.<n>.sh`, a Python module with constants. It needs fewer rows, but `board sweep --help` must list adapter flags and `cmd_sync` must build the flag lines without importing Python (the dispatch suite stubs `python3`), so bash still has to read a declared list of flags, secrets, verbs and legs. A file naming convention cannot carry flag names, config keys and help text.
3. One manifest per adapter, read by a small Python loader and a small bash reader. Adds one file format and two readers of it. The engine already has the right Python interface; the manifest adds only what core cannot know any other way (which names exist and which flags and verbs belong to them).

### Chosen approach + why

Approach 3, cut to what the row's Done needs. The interface that already exists is the duck-typed source object in `sources/*.py` (`name`, `sync_fields`, `read()`, `apply()`, and optional `create_only`, `pull_only`, `skip_kw`, `binding`, `preflight()`, `preview()`). It is kept byte for byte. Added, and nothing else: an entry module with `build()` per adapter, three optional named hooks (`guard`, `body_expander`, `brief_decisions`), one optional attribute (`bound_marker_re`), and a manifest of eight row kinds so bash can enumerate flags, secrets, verbs, sweep flags and legs without importing Python. Rejected: a base class (nothing to share), a config-declared import path (executes arbitrary project code), a config key for the adapter directory (nothing in the row's Done needs it; `[sync] apps` already selects adapters by name), and a new daemon or registry service (a personal host needs none).

Config: loading is by use, as it is today. `[sync] apps` still selects spokes, `--mirror-hermes-home` still turns the mirror leg on, a verb runs when called. The loader scans one directory: the value of the environment variable `KIT_ADAPTERS_DIR` (an absolute path; tests and out-of-tree adapters use it), else `lib/adapters/` of the running kit. No `kit.toml` key is added, so no project file can influence which code the loader runs. No "enabled" list exists, because one that defaults off breaks the hourly sweep at merge (`--mirror-hermes-home` would exit 64) and one that defaults on adds nothing. A host whose adapter directory is empty gets core only (defined below).

Cuts made at validation (what each would have cost, what breaks without it): the `[adapters] dirs` key and its root-only resolution (nothing in the Done needs it); the colon list of directories with clash and missing-directory warnings (one directory covers every test); the `name`, `module`, `report` and `mirror-label` row kinds (the name is the directory, the module is always `adapter.py`, the label and heading are `const` rows, the report is a `hook` row); `prepare` (the legacy state copy runs at the top of the Reminders `build`); `adapters_export` (the environment variable already reaches children); `conftest.py` and `Registry.module` (tests import their own sibling modules directly; the conformance test is what goes through the loader); the per-adapter `tests/` directories and most `fixture-opts.json` files (one flat `lib/adapters/tests/` and conformance defaults; the Notion adapter keeps one, because its map and JSON options reject placeholder strings); `test_legacy_inbox.py` (the case joins `test_core.py`); two planted fixture files (the purity test writes them to `$TMPDIR`).

### Extensibility & boundaries

- Load-bearing dimension: the number of adapters. Cost of the sixth: one directory with a manifest and an `adapter.py`; no edit to core. The conformance test and the flag-surface check iterate manifests, so they cover it without edits.
- Boundaries: core never imports an adapter by name and never reads an adapter's files except `adapter.tsv`. An adapter may import core (`sync_core`, `cockpit`, `kit_data`, and the sweep helpers) and its own siblings, never another adapter; the one cross-adapter need (Hermes expanding a Notion page body) goes through a named hook the loader passes in.
- Honest scope of the hooks: `guard` and `bound_marker_re` exist because of the Notion pull intake, `body_expander` links two adapters, `brief_decisions` and the `mirror-label` constant exist because of the Hermes mirror, and the legs and verbs are the Hermes bridge. Each is optional and no core branch keys on an adapter name; the grammar is not claimed to be more general than that. Core keeps two app-shaped ideas under neutral names: the sweep records a failed leg named `mirror` in the health state, which `board-health` already persists under that key; and `board-health` and `board-brief` read a "mirror target" through two commands (`boards list --json` and `--board SLUG list --json`) and the `origin: <repo>:<id>` card marker. A second mirror target must satisfy that reader contract, which `lib/adapters/README.md` states.
- Failure containment: an adapter is imported only when something names it (an app in `--apps`, a verb, a leg, a hook provider). A broken adapter fails the runs that name it, loudly, and never touches the rest.

## Technical Design

Runtime floor. The live interpreter is the first `python3` on the job's PATH: the cron wrappers put `/opt/homebrew/bin` first (Python 3.15 on this host), an interactive shell resolves 3.12. `/usr/bin/python3` (3.9.6) cannot run the engine today: `lib/sync/sync_core.py` evaluates `dict | None` annotations at import, so `PYTHONDONTWRITEBYTECODE=1 /usr/bin/python3 lib/sync/backlog_sync.py --help` ends in a `TypeError` before this change. This spec does not lower or raise that floor. New code (the loader `adapters.py`, every new `adapter.py`, `link.py` additions, the three leg scripts, `bridge.sh`, `board-lib.sh`, `adapters.sh`) stays inside 3.9: `from __future__ import annotations` first in each new Python file, no `match`, no `X | Y` evaluated at runtime, no `zip(strict=)`. Moved files change only import and path lines, so they keep today's floor. Bash code is bash 3.2 clean (`/bin/bash` on macOS runs `board-sweep` and `board-sync-cron`): no `mapfile`, `readarray`, associative arrays or `${v,,}`; empty arrays expand as `${a[@]+"${a[@]}"}`; `IFS=$'\t' read` collapses empty fields, so a manifest row never carries an empty field (`-` is the placeholder). `tests/test-adapters.sh` checks both rules (see TASK-S).

### Interfaces (I/O contract)

#### Manifest: `lib/adapters/<name>/adapter.tsv`

Tab separated, UTF-8, one row per line, first field is the row kind, `#` in column 1 starts a comment, blank lines are skipped. No row has an empty field. An unknown kind is ignored with one stderr warning from the loader. A known kind with a bad field is a load error: exit 1, one line `adapters: <file>:<line>: <what is wrong>`. The adapter name is its directory name; the entry module is `adapter.py` and is required when the manifest has an `app`, `guard` or `hook` row.

| Row | Fields | Meaning |
|---|---|---|
| `app` | `<app> <mode>` | app name and mode `two-way`, `create-only` or `pull-only`. The engine checks, after `build` returns an object, that its `create_only` and `pull_only` attributes agree with the mode, and exits with a message naming the app if not |
| `opt` | `<flag> <key> <scope> <help...>` | engine flag `--<flag>`, filled from `[sync] <key>`, stored by argparse as `dest=<key>` and handed to `build` as `opts[<key>]` (`None` when absent; an empty string when the caller passes `--<flag> ""`). `scope` is exactly `-` or `root` (`root`: operator and kit-root files only, never a project `.kit.toml`). `help` is the argparse help text (the loader doubles any `%`) |
| `secret` | `<ENV> <key>` | before the engine starts, `cmd_sync` resolves the 1Password ref in `[sync] <key>` into env var `<ENV>`. Always root-only. Keychain cache read first (`secret-cache-read --ttl 21600`), raw `op read` as the fallback, skipped when `<ENV>` is set and non-empty, never an argv flag. The loop runs in the current shell (process substitution, not a pipe) so the export survives |
| `verb` | `<verb> <script> [<arg>...]` | `board <verb> ARGS` runs the script with the manifest args first, then `ARGS`; `.py` runs under `python3`, anything else under `bash`. Env: `KIT_LIB` (absolute `lib/`). One script may serve several verbs through the leading arg (`verb mirror bridge.sh mirror`) |
| `sweep-opt` | `<flag> <ENV> <help...>` | `board sweep --<flag> VALUE` is accepted, exported to legs as `<ENV>`, and listed in `board sweep --help` |
| `leg` | `<phase> <script>` | a sweep leg; `phase` is `after-sync` or `last` (see Legs). The leg name is the script basename without its extension |
| `const` | `<name> <value...>` | a constant core reads from the first adapter that declares it. Defined: `mirror-label` (the display word in health and brief lines about the mirror leg; fallback `mirror target`) and `inbox-heading` (the heading line for a new intake section; fallback `### Intake inbox`) |
| `hook` | `<name>` | the entry module exports a function `<name>`. Defined: `guard`, `body_expander`, `brief_decisions` |

Load-time grammar. `adapters_rows` and `adapters_verb` (bash, in awk) and the Python loader each validate every row they return and fail with the same `adapters: <file>:<line>: ...` line; T4 feeds every bad-row fixture to both readers and compares the messages. Adapter directory names match `^[a-z][a-z0-9-]*$`; a directory with no `adapter.tsv`, or whose name starts with `.` or `_`, is skipped silently. `app`, `verb` and `flag` match `^[a-z][a-z0-9-]*$`; `key` matches `^[a-z][a-z0-9_]*$`; `ENV` matches `^[A-Z][A-Z0-9_]*$`, is none of `PATH`, `HOME`, `IFS`, `ENV`, `BASH_ENV`, `SHELLOPTS`, `BASHOPTS`, `PS4`, `PROMPT_COMMAND`, `CDPATH`, and starts with none of `LD_`, `DYLD_`, `PYTHON`, `KIT_`, `SWEEP_`, `BOARD_`, `GIT_`, `SSH_`, `OP_`, `NODE_`. Every `<script>` and `adapter.py` is a regular file (a symlink is a load error) whose path text stays inside its adapter directory (relative, no `..`; a text check, so bash 3.2 needs no `realpath`); the file's existence is checked when its verb or leg runs, not at load. A flag, key, ENV name, verb or app named by two adapters is a load error, and so is a `const` name declared twice and a singular hook (`body_expander`) declared twice (`guard` and `brief_decisions` are plural). An `opt` flag or key equal to a core engine flag or dest, or a `sweep-opt` flag equal to a core sweep flag, is a load error (the engine's argparse and `board-sweep`'s own case list supply the sets). An adapter that declares a `secret` row declares no `opt` of scope `-` whose key ends `_url`, `_host`, `_endpoint` or `_target`, so a project file cannot point a root-resolved secret at a host of its choice. A verb equal to a core verb is a load error. Core verbs are a static `CORE_VERBS` list in `adapters.sh`, read by `adapters.py`: the `main()` labels of `board.sh` that are not adapter verbs (`all queue sync publish sweep init capture promote normalize run work health brief help`, and `state-check` once that change lands) and the backlog verbs `board next get row set dedupe dedupe-all lint add states machine`. `lib/adapters/tests/test-adapters.sh` asserts the list equals the `main()` labels plus the first token of each `|` alternative inside the braces of the `backlog.sh` usage line (so `--status` is not a verb), and that the five real Hermes verbs load against the real `board.sh` and `backlog.sh`. Manifest errors are global by design: one bad manifest stops every run that loads the registry (the containment promise covers imports of adapter code, not manifest grammar). The lint guards against accidents; the trust boundary is who can write the adapter directory.

Directory. The loader scans one directory: `KIT_ADAPTERS_DIR` when set (an absolute path; an empty or relative value exits 1 `adapters: KIT_ADAPTERS_DIR must be an absolute path`), else `lib/adapters/` of the running kit, derived from the realpath of the loader file (`adapters.py`; `BASH_SOURCE` of `adapters.sh`) plus `../adapters`, never from cwd, `KIT_PROJECT_ROOT`, `DWARVES_KIT` or any config value (T4 has a decoy case: a fixture repo with its own `lib/adapters/decoy/{adapter.tsv,adapter.py}` whose module writes a marker file, with cwd and `KIT_PROJECT_ROOT` pointing at it). `KIT_ADAPTERS_DIR` replaces the in-tree directory, it does not add to it: an extension directory symlinks the built-ins it wants, and `board help` shows the effective directory. A directory that does not exist means zero adapters, silently; one that exists and cannot be read is a load error (exit 1, one line), so a permission slip on the `server` account is loud. The variable is an operator and test seam with the trust of `PATH`: it selects code that runs with the caller's full environment, so `lib/adapters/README.md` says never to point it at a path a project or another account can write, and lists the project-writable ways an environment variable gets set (`.claude/settings.json` `env`, `.envrc`, mise). `board.sh`, the engine, `board-sweep`, `board-health` and `board-brief` each read the variable themselves, so no caller has to export it.

#### Python loader: `lib/sync/adapters.py` (core)

`load() -> Registry`. It reads manifests only; it imports an adapter module when something names that adapter. `Registry` exposes `apps` (app to adapter and mode), `opts` (the opt rows), `create_only_apps()`, `pull_only_apps()`, `mode(app)`, `build(app, opts, ctx)`, `hooks(name, only=None)` (callables from the adapters that declare the hook, limited to adapters that provide an app in `only` when given), `hook(name)` (the first provider's callable, or `None` when no adapter declares the hook), `const(name, default)`. The loader puts `lib/sync`, `lib/sync/sweep` and `lib/config` at the front of `sys.path` and the adapter's own directory at the end, before it imports an adapter, registers the module as `kit_adapter_<name>` in `sys.modules` before `exec_module`, and keeps those entries for the life of the process. Before it executes an adapter it checks every `*.py` stem in the adapter's directory: if `sys.modules` already holds that stem with a `__file__` outside the directory, it exits 1 `adapters: <adapter>: module name <stem> already provided by <other>` (the stem `adapter` is exempt, it loads as `kit_adapter_<name>`). A `Registry` execs a fresh module per load and replaces earlier `kit_adapter_<name>` entries, and tests that reuse an adapter name run in a subprocess or purge those entries in an autouse fixture. Sibling module names are unique across adapters, and the conformance test asserts it, that each module's `__file__` sits in its own directory, and that no sibling stem resolves to a standard-library or core module under `python3 -I`. An unknown app name in `--apps` exits 1 before the lock: `no adapter provides <app> (searched: <dir>)`. A hook provider that declares a hook and then fails to import, or lacks the named function, makes the run exit non-zero with one line `hook <name> from <adapter> failed: <error>`; `hook()` returns `None` only when no adapter declares the hook at all.

#### Verbs, legs, hooks

- `board.sh main()`: after the core cases, before the fall-through to `cmd_board_single`, one lookup, only for a first word that is not a core verb: `adapters_verb "$first"`; on a hit it exports `KIT_LIB` (an output for out-of-tree scripts) and `exec`s the script (`python3` for `.py`, `bash` otherwise) with the manifest args then the caller's args. A miss falls through unchanged, so with no adapter `board mirror` ends in `backlog.sh`'s usage line and exit 64, exactly as any unknown word does today (and `board mirror` called by the sweep leg logs `mirror rc=64` and records the mirror leg as failed).
- Verb scripts may source `$KIT_LIB/board/board-lib.sh` (new, extracted from `board.sh` in TASK-L): the `OPT_*` defaults, `_parse_flags`, `_default_repo_root`, `_resolve_repo_root`, `_repo_root_for`, `_mega_rollups`, `_iso_to_utc_z`, `MEGA_SH` (recomputed as `$KIT_LIB/mega/mega.sh`) and the `box.sh` source. Moved scripts derive `KIT_LIB` from their own location and ignore the environment (bash: `KIT_LIB="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"`; Python: `Path(__file__).resolve().parents[2]`), so a stale or hostile inherited value redirects nothing and a direct call (a test, or the `--remote` ssh path) works; they restore `set -euo pipefail` where the old function ran under it. `board.sh` sets and exports `KIT_LIB` before it sources `board-lib.sh`. The `KIT_LIB` and `MEGA_SH` rows of `lib/config/module-registry.md` stay true (script-local, never read from the environment).
- Legs. `board-sweep` reads the `sweep-opt` rows once at start; an argument that no row and no core flag accepts ends `board sweep: unknown arg: <arg> (adapter dir: <dir>)` with exit 64, before any sync, so a job that passes `--mirror-hermes-home` to a kit with no hermes adapter fails loudly and at once. Every `sweep-opt` variable is exported to legs, empty when not given. `after-sync` legs run after the per-repo loop and the `--extra-board` loop, before the digest posts, in manifest order; `last` legs run right after the health leg, before the on-clean hook and before the dry-run scratch-state removal. The runner starts a leg as `"$BASH" <script>`, so it runs under the sweep's own interpreter (the sweep is `#!/bin/bash`, 3.2 on macOS, as the inline legs are), with env `SWEEP_NAME`, `SWEEP_BOARDS`, `SWEEP_REPO_ROOT`, `SWEEP_DRY_RUN` (0 or 1), `SWEEP_BOARD_CMD`, `SWEEP_HEALTH_BIN`, `SWEEP_HEALTH_STATE` (the path after the dry-run swap), `KIT_LIB` and the `sweep-opt` variables. It exports no sweep token, `GH_TOKEN` or `GIT_ASKPASS` to a leg (the sweep keeps its token as a shell variable today), and the leg's stdout and stderr pass through unbuffered into the sweep log.
  - Gating and result. A leg whose gating option is empty (`mirror` and `expire` without their `sweep-opt` values) exits 0 and prints nothing; the link check always runs, as today. A leg records its own health result in an EXIT trap, prints its own `mirror rc=<n> ...` or `expire rc=<n> ...` line, and exits 0 whenever it reached that line, whatever the wrapped command returned. A non-zero exit means the leg itself broke: the runner prints `  leg <name> exited <rc> (non-fatal)` on any non-zero leg exit and, for the leg named `mirror`, records `board-health record --leg mirror --rc <rc>` when the leg's trap did not, so a crashed mirror leg shows as failed in the next digest instead of keeping its last green mark. A leg that runs and fails never changes the sweep's exit code, as today, and the on-clean hook stays gated on `rc_any` only.
  - Missing script. Existence of a leg or verb script is checked when it runs, so a missing leg fails that leg only and never the sweep before the per-repo syncs ran: the runner prints `  leg <name> failed: <script> not found`, records the same `mirror` fallback, and sets the sweep's exit code to 1 (the on-clean hook is held).
  - Signals. The runner traps INT and TERM, makes the signal reach the leg (a background child of a non-interactive bash ignores SIGINT and cannot trap it, so the runner starts the leg under job control or an equivalent that a test proves, and sends TERM), waits until the leg has exited, then exits 130 or 143 at once: no later leg, no digest post, no health leg, no on-clean hook, as today's inline mirror trap does. The mirror temp-file cleanup trap moves into `legs/mirror.sh`, so it runs on that TERM.
- `board-health` and `board-brief`: the words "Hermes mirror", "hermes mirror" and "the Hermes card" become `f"{label} mirror"`, `label.lower() + " mirror"` and `f"the {label} card"` with `label = reg.const("mirror-label", "mirror target")`. `board-brief` replaces `HM.check_links()` and the `hermes_links` read with the providers of `brief_decisions`; a provider that raises, fails to import or lacks the function adds one attention line `report hook <adapter> failed: <ExceptionClass>` (adapter name and exception class only; the full text goes to stderr) and the brief still exits 0. This is the brief's own rule and differs from the loader's rule for `body_expander` on purpose: a missing stale-link line must not stop the daily brief, a missing page body must not create a bodiless card. The persisted health key `hermes_links` is read and written only inside the Hermes adapter.

## Task Breakdown

Atomicity note. Each task edits at most 5 files that are not tests, fixtures, `git mv` renames or pins, and has at most 5 acceptance clauses (numbered below). A rename whose only edit is an import or path line is listed under `moves`; a pin is a suite, doc or comment line whose only change is a moved path string (one line each). Test and fixture files a task adds are named in its Files list and are not counted. Each task ends with the repo green: its named suites, `bash tests/test-sync-characterize.sh` (the golden capture of TASK-A1 and TASK-A2; the only diffs allowed are rows in `tests/fixtures/sync-characterize/deltas.txt` whose tag is in the closed list under Invariants (Output), and a task that causes one adds its row in its own commit), and, at the end of a phase, `bash tests/run-all.sh --changed`. Generated registry files (`docs/reference/FEATURES.md`, count strings) are regenerated in the task that adds or moves a suite: `bash lib/registry/feature-registry.sh generate`, then `bash tests/test-meta-docs-registry.sh`. New suites use `grep -E` or `git grep`, never `rg` or `fd` (the contract lint bans them in suites); the `rg` lines in this spec are builder-side commands. Each new Python file starts with `from __future__ import annotations`. All tasks run on one branch (`refactor/sync-adapters`), serially, in the order below, one commit each, merged as one PR (see Risk and rollback). Nothing here runs in parallel: one working tree has one writer. A builder never starts a task whose dependency commit is not on the branch. Tick a task's checkbox in the same commit that finishes it.

## Edge Cases

1. A manifest row of an unknown kind: ignored with one warning; the rest of the adapter loads. A known kind with a bad field: the load fails with `adapters: <file>:<line>: ...`.
2. Two adapters declare the same app, flag, key, ENV name or verb: load error naming both files.
3. `[sync] apps` names an app no adapter provides: exit 1 `no adapter provides <app> (searched: <dir>)`, before the lock; nothing is synced, including the apps listed before the unknown one.
4. A Hermes flag is passed to `backlog_sync.py` while the Hermes adapter is absent: argparse exits 2 with its usual "unrecognized arguments". A sweep leg flag with no adapter: `board sweep: unknown arg: <arg> (adapter dir: <dir>)`, exit 64, before any sync.
5. `KIT_ADAPTERS_DIR` is relative or empty-but-set: exit 1 `adapters: KIT_ADAPTERS_DIR must be an absolute path`.
6. The adapter directory does not exist: zero adapters, no warning (the directory is named in every "no adapter provides it" message).
7. The Notion adapter is absent while the Hermes relay runs: the hook is `None`; the card is created with the unexpanded body, the same outcome as today's "page body unavailable" path. The Notion adapter is present and broken: the run exits non-zero and creates no card.
8. A leg script is missing or unreadable (checked when the leg runs, after the per-repo syncs): the sweep prints `leg <name> failed: <script> not found`, records the mirror leg as failed and ends with rc 1. A leg that runs and exits non-zero: observational, `leg <name> exited <rc> (non-fatal)` on any non-zero exit and the `mirror` fallback record; the sweep's exit code is unchanged. INT or TERM during a leg ends the sweep at once with 130 or 143.
9. A board has two `### Reminders inbox` headings: the first receives rows, as today.
10. A manifest verb equals a core verb (a name in `CORE_VERBS`): load error, so it cannot shadow `next`, `get`, `set`.
11. `board sweep` and `board health` run as the `server` account through `/Users/Shared/dwarves-kit`: adapter directories are 755 and files keep their mode bits, so it can read and run them; an adapter directory that exists but cannot be read is a load error, so the first dry run fails loudly instead of showing the `mirror target` label.
12. Old state written by the previous kit (`<app>.state.json`, snapshot, `health-state.json`) is read by the new code unchanged, and the reverse holds after a revert.
13. `board sweep --dry-run`: legs receive `SWEEP_DRY_RUN=1` and `SWEEP_HEALTH_STATE` points at the scratch copy, exactly as the inline legs used the scratch copy.
14. An adapter that imports another adapter directly: not allowed; the conformance test imports each adapter alone in a fresh interpreter, and asserts sibling module stems are unique.
15. A run names no Notion app but carries a `notion_db` equal to the pull database, for example `--apps hermes`: it proceeds, where the old engine refused it; nothing in such a run can write to that database.

## Risk and rollback

What breaks if a move is wrong: this host runs the checkout, so the first hourly sweep after merge (`mini.sync`, stage `board-sync-all`) and the next neko-chief `health` or `brief` dry run are the first live readers. A wrong flag or an unknown sweep argument ends the sweep with exit 64 or 2 before any sync (loud). A wrong path inside a mirror, expire or link leg does not end the sweep nonzero: those legs are observational today and stay so, so it shows as a nonzero `mirror rc=` or `expire rc=` line, a `link check failed` line and a failed mirror leg in the health digest, and the sweep still ends `rc=0`. A missed `KIT_LIB` self-location error fails one leg the same way. The Notion intake tick on the Mini is isolated by its pinned `KIT_REF` and cannot be hit by the merge.

Rollback: ship the whole change as one PR with one commit per task, squash merged, so one command undoes it: `git revert -m 1 <merge commit>` (or `git revert <sha>` for a squash) on `master`. No persisted file changes name or shape, and the intake heading is unchanged while the Reminders adapter is installed, so there is nothing to migrate back and no board text the old code would misread.

Pre-merge gate: `kit:battery`, then the Verification list. The build loop ends at an open PR and a report; the lead queues the merge and the post-merge commands, and nobody merges from the build. Post-merge, read only, after the merge time is known (merge outside the hourly window, and discard any tick that started before the merge):

```bash
bash ~/.claude/dwarves-kit/bin/board sweep --help | rg -e 'Usage: board sweep' -e '--expire-kinds-file'
LOG=~/Library/Logs/dwarves-kit/board-sync-all.log
tick=$(awk '/board-sync-all: start/{b=""} {b=b $0 "\n"} END{printf "%s", b}' "$LOG")
printf '%s' "$tick" | head -n 1                                  # its start time must be later than the merge
printf '%s' "$tick" | grep -q 'board-sync-all: end rc='          # the tick finished
printf '%s' "$tick" | grep -q '^  mirror rc=0' && echo mirror-ok
printf '%s' "$tick" | grep -q '^  expire rc=0' && echo expire-ok
printf '%s' "$tick" | grep -Ec 'link check failed|leg .* (exited|failed)|^  (mirror|expire) rc=[1-9]' || true   # must print 0
```

A tick that holds `mirror skipped` is not counted: wait for the next tick. Compare the tick's per-repo `<name> rc=` lines with the last tick before the merge; the final `end rc=` line is not a gate on its own (4 of the last 164 ticks ended `rc=1` before this change, from repos whose own sync failed). Then `ls -ld ~/.claude/dwarves-kit/lib/adapters` shows a directory the `server` account can read (mode 755).

## Decision Log

- DEC-A: adapters live in `lib/adapters/<name>/`. Why: `~/.claude/dwarves-kit` links `bin`, `lib`, `hooks` and `kit.toml` only and `install.sh` copies `lib` and `bin`, so a new top-level directory such as `integrations/` is not reachable on this host or in a pinned install; `lib/adapters` is outside both core roots, so the row's grep comes back empty. Rejected: `integrations/<app>/` (unreachable), `lib/sync/adapters/` (inside the grep scope).
- DEC-B: enablement is by use, not by a new enabled list; the loader scans one directory, `lib/adapters/` or `KIT_ADAPTERS_DIR`. Why: an off-by-default list breaks the hourly sweep at merge, an on-by-default list adds nothing. With an empty adapter directory, core works and the connectors are absent, which T2 pins.
- DEC-C: no config key selects the adapter directory (the draft's `[adapters] dirs` is cut). Why: the row's Done does not need it, `[sync] apps` already selects adapters by name, and a key that chooses code to run would need root-only resolution, a registry row, a shadow note and tests for a threat the environment variable does not add (it has the trust of `PATH`).
- DEC-D: GitHub becomes a fifth adapter. Why: same interface, one file plus its test, and it lets the engine drop the if-chain and the legacy sets entirely instead of keeping a one-branch fallback. Kept at validation against a cut proposal: leaving it would keep a `sources/` package in core and a second code path.
- DEC-E: the dated records (`lib/sync/docs/proof-of-done.md` and `lib/sync/docs/specs/SPEC-001` to `SPEC-004`) move untouched to `lib/adapters/docs/`. Why: the literal grep must return nothing, and a dated record is never reworded; `spec-find` resolves any `*/docs/specs/`, so they stay findable. The alternative, a purity exemption list for five paths, would leave the row's literal command non-empty.
- DEC-F: the intake heading stays `### Reminders inbox` while the Reminders adapter is installed, supplied by its `inbox-heading` constant; core carries only the neutral default `### Intake inbox`. Why: the draft's rename would have written `### Intake inbox` on 14 of the 16 registered boards at their first intake row, and the pinned Notion intake clone (and a revert) would then add a second `### Reminders inbox` section. A constant gives zero visible change on this host and no revert asymmetry.
- DEC-G: `board status` (mirror staleness and its `--with-mega` rollup) goes with the Hermes adapter. Why: the verb reports the bridge snapshot; `board --with-mega` stays in core for the plain rollup. With no Hermes adapter `board status` is an unknown verb. `_mega_rollups`, `MEGA_SH` and `_iso_to_utc_z` move to `board-lib.sh` so the moved verb keeps working.
- DEC-H: the Hermes relay gets the Notion page-body expander through a hook the loader passes in, not a core import. Why: core must not know that one adapter feeds another. Absent provider means `None`; a provider that is declared and broken is a loud failure, because a silent `None` would create cards without bodies that are never recreated.
- DEC-I: sweep legs have two phases (`after-sync`, `last`). Why: it reproduces today's order exactly (mirror, expire, digests, health, link check), so log text and order are byte for byte. A leg whose script is missing is a broken install and fails the sweep (rc 1, checked when the leg runs, after the per-repo syncs); a leg that runs and fails stays observational, as today; INT or TERM during a leg ends the sweep at once.
- DEC-J: one PR, one commit per task, six builder phases (a phase may end at any task boundary; the next builder resumes at the first unchecked task). Why: the host runs the checkout, so each merge is live; one PR gives one revert.
- DEC-K: the text deltas are a closed list of eight tags (`describe-line`, `board-help`, `sweep-help`, `apps-default`, `apps-hint`, `unknown-app`, `sweep-unknown-arg`, `health-brief-help`), recorded as `<section><TAB><tag>` rows in `deltas.txt`; a ninth stops the build and goes to Open questions. The draft said four and was wrong: two core lines (`--apps` default and the config hint) name Reminders and cannot stay. The digest parser keys on the `+ board`, `~ board` and `✓ board` lines, which do not change. Three behavior deltas no golden hunk shows are stated under Invariants and tested.
- DEC-L: the loader is core code in `lib/sync/` (`adapters.py`, `adapters.sh`), not a new module under `lib/`. Why: `lib/sync` already owns the engine, and a new top-level module would need a `tool.toml` and a row in the kit contract.
- DEC-M: `hermes_target` and `hermes_home` keep scope `-` (project files may set them), as `cmd_sync` reads them today. Known risk, not new: a project `.kit.toml` value starting with `-o` becomes an option of the local `ssh` call, so it is command execution as the operator account on the host that runs the sweep, and any `sudo:<user>` is accepted (Not in this spec, item 7). Moving them to `root` would break live repos that set them in project files; the owner decides that separately.
- DEC-N: one added module suite, `lib/adapters/tests/test-adapters.sh`, carries the adapter tests and the bash cases. Why: `bin/test-affected` selects suites by module and by path reference; without a suite under `lib/adapters/tests/` a change to an adapter selects nothing.
- DEC-O: the Python floor is not changed by this spec. New files stay 3.9-clean, moved files keep today's floor (the engine needs 3.10 or newer at import already), and tests assert the new files only.
- DEC-Q: lead decisions at the end of validation: golden section (1) compares normalized argv; `--apps` has no engine default; legs run as `"$BASH" <script>` and own their result record; moved scripts ignore an inherited `KIT_LIB`; core verbs are a static list; the build loop ends at an open PR; no third validation round.
- DEC-P: validation cuts (what each saved): `[adapters] dirs`, colon-list directories with clash warnings, the `name`, `module`, `report` and `mirror-label` row kinds (now 8 row kinds, was 11), `prepare`, `adapters_export`, `conftest.py`'s `adapter_module` and `Registry.module`, per-adapter test directories and fixture files, two planted fixtures, `test_legacy_inbox.py`, the second README pass; `fixture-opts.json` for four of five adapters. Rejected cuts: dropping the GitHub adapter (DEC-D), moving the per-adapter READMEs into one file (the old README's per-app text needs a home per app; one file would repeat the single-file problem), replacing the bash reader with a wrapper over `python3` (the dispatch suite stubs `python3`).
