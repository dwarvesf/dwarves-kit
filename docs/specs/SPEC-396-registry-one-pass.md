## Problem

`lib/registry/feature-registry.sh generate` projects `docs/FEATURES.md`. For each of about 124 features it ran `grep -lE` over every spec (4.6 MB) and every test (3 MB), plus a pipeline per cell. That is about 46 s of CPU on a quiet host and 50 s under load. `hooks/ship-gate.sh` runs it on a push that moved an input, `tests/test-meta.sh` and `tests/test-meta-docs-registry.sh` run it for the freshness pin, and the docs-registry suite ran it three times (about 138 s of that suite).

## Solution

### Approaches considered

1. **One awk pass for all features.** Read each corpus file once, build token to files, answer every feature by lookup, format the cells in the same awk.
2. **One `grep -o` with all tokens.** Rejected: `-o` consumes the boundary character, so two tokens separated by one space lose the second match, and a PCRE lookaround is not portable to macOS grep.
3. **Cache the result across runs.** Rejected: the registry has to be exact on every run; a cache key over 7 MB of inputs is the same scan.

### Chosen approach + why

Approach 1. The old match is `(^|[^A-Za-z0-9_-])TOKEN([^A-Za-z0-9_-]|$)` on one line. For a token made only of `[A-Za-z0-9_-]` both neighbours lie outside the class, so the match is exactly a maximal run of class characters equal to the token. The awk splits each line on the complement class and looks the runs up in a set. A token with any other character (`foo.sh`, `foo run`) keeps its regex, tested only on lines that contain the token's leading literal run. Output is the same bytes by construction, and the proof checks it differentially.

```
                        END: per key, union files, format cells     tables use ref_lookup
```

## Design

### Interfaces (I/O contract)

`feature-registry.sh generate [outfile]` and `check [--fix] [outfile]`: same arguments, same bytes out, same exit codes. One addition: `check` honours `FEATURE_REGISTRY_KEEP=<path>` and copies its generated bytes there, so a caller that needs the verdict and a second copy pays for one run. Only POSIX awk is assumed; the one-true-awk shipped with macOS, mawk and gawk all produce identical output.

### Boundaries and failure modes

- The Specs cell takes the number from the `SPEC-<digits>-` file prefix and sorts numerically, like `sort -uV` on those strings. A spec file name without that shape falls back to its full path, as the old `sed` did; no such file exists today.
- Cells format in the awk, so the shell spawns no pipeline per row. The shell keeps the per-verb `grep` over `hooks/*.sh` (about 40 small files) that finds the hooks calling a verb's script.
