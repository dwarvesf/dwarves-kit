## Acceptance Criteria
- [ ] AC-1: `goal.sh draft <args>` execs `goal-drafts.sh` with the remaining args unchanged.
- [ ] AC-2: `goal.sh drafts <args>` (alias) execs `goal-drafts.sh` identically to AC-1.
- [ ] AC-3: `goal.sh registry <args>` execs `goal-registry.sh` with the remaining args unchanged.
- [ ] AC-4: `goal.sh merge <args>` execs `mega-merge.sh` with the remaining args unchanged.
- [ ] AC-5: `goal.sh stack-merge <args>` execs `stack-merge.sh` with the remaining args unchanged.
- [ ] AC-6: `goal.sh handoff <args>` execs `handoff-gen`, which itself execs `python3 handoff/handoff_gen.py <args>` (double exec chain).
- [ ] AC-7: `goal.sh` with no arguments prints usage (the comment-stripped lines 2-13 of the file) and exits 0.
- [ ] AC-8: `goal.sh -h`, `goal.sh --help`, and `goal.sh help` all print the identical usage output and exit 0.
- [ ] AC-9: `goal.sh <unrecognized-verb>` prints exactly `goal: unknown verb '<verb>' (try: goal --help)` to stderr and exits 1.
- [ ] AC-10: every forwarding branch uses `exec` (process replacement, not a subshell), so the caller sees the sibling script's exit code directly with no translation.
- [ ] AC-11: a missing/unreadable sibling script surfaces as the child bash's own error (`bash: <path>: No such file or directory`, exit 127), not a goal.sh-authored error message.
