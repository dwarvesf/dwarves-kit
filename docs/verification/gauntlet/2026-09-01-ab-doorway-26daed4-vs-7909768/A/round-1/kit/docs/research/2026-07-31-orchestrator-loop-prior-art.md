# Orchestrator-loop prior art: deep survey (2026-07-31)

Operator ask after SPEC-217 shipped: find similar open implementations of a backlog-driven autonomous dev loop to learn from. Fresh-context web survey, GitHub-focused, run 2026-07-31. Rows filed from this doc: ID-459 (notes-cell sanitization), ID-460 (convergence + stale-window quarantine), ID-461 (draft-PR default + per-row spend ceiling). The til candidate (decision-ledger pattern writeup) is tracked on the ops-toolkit board.

## Verdict

Four repos are worth study time, and only four. Ranked:

**1. github/gh-aw (GitHub Agentic Workflows), 4.8k stars.** The only project in the survey that leads with a security posture instead of bolting one on. Structural idea: the agent container runs read-only by default and can never write to external state. All writes route through a separate post-agent job consuming sanitized `safe-outputs`, gated by a dedicated threat-detection job that inspects buffered agent output for secret leakage and malicious patches before the write job runs. Three-container topology: agent (read-only repo), `gh-aw-firewall` (Squid proxy, default-deny domain allowlist via iptables), `gh-aw-mcpg` (MCP gateway holding the only copy of the GitHub PAT, so credentials are physically unreachable from the agent process). It also sanitizes untrusted issue text before the model sees it: `@mention` neutralization, autolink escaping, script-tag defusing, non-HTTPS URI filtering, 0.5 MB / 65k line caps, ANSI control-character stripping. The kit has hardened the POINTER path (symlink-aware containment on watcher-planned rows) but the loop still reads free-text board Notes cells into an agent with write access. gh-aw is the reference shape for closing that.

**2. jnuyens/gsd-plugin (Buildomator), 84 stars, GSD successor.** One mechanism worth stealing outright: verification gaps auto-route by severity, goal-breaking gaps escalate to a follow-up phase, minor gaps park to backlog, no prompt. That is exactly the shape of the retro-suggestions staging buffer, already solved and running. Also worth reading: its `HANDOFF.json` (19 fields, CI-validated against `schema/handoff-v1.json`) written by a PostToolUse hook throttled to one write per minute, specifically to survive Claude Code's silent microcompact. After an unexpected kill, state is at most ~60s stale.

**3. lee-to/aif-handoff, 269 stars.** The closest architectural sibling to the kit's loop and the only one with a real answer to runaway loops. Pipeline `backlog -> planning -> plan_ready -> implementing -> review -> done -> blocked_external`, coordinator is event-driven over WebSocket with 30-second poll fallback, liveness via `lastHeartbeatAt`. Two mechanisms to steal: (a) convergence detection, when review stops converging the task moves to `done` with `manualReviewRequired=true` rather than looping forever; (b) heartbeat-staleness force-moves a dead stage to `blocked_external`, and after max stale retries the task is quarantined. The watcher dedups on terminal journal verdict, which handles COMPLETED rows; it does not obviously handle a row whose window died mid-run.

**4. saltbo/agent-kanban, 425 stars.** Read only for two things. Atomic claims via D1 SQLite batch operations (race-free task claiming, the honest version of what a lock file approximates), and per-session Ed25519 keypairs where each agent signs its own JWTs, giving a cryptographic fingerprint following it across tasks, commits, and PRs. The only provenance mechanism in the field.

**Where the kit is already ahead, honestly.** `watch-board.sh` is more careful than anything surveyed. Dry-run is the default and `--apply` is required before a window opens; almost every other project defaults to firing. The idempotency rule is better reasoned than the field: treating `gated` as terminal alongside `done` (because gated-final merge is the default posture, so a done-only rule re-plans every gated row forever) while keeping `error`/`stalled`/`skipped` retryable is a distinction none of these repos make. Symlink-aware realpath containment applied to the watcher's OWN generated plan (a row sourced from a free-text Notes cell is not operator-authored, so it does not inherit the operator-authored exemption) is a threat-model refinement found nowhere else. The per-run `--max` budget cap plus explicit `--repo-name` pinning guidance for cron (the slug is the dedup key) is the kind of detail these projects discover after an incident. Wavefront scheduling with worktree isolation is level with GSD and aif-handoff, ahead of everyone else.

**The genuinely novel part.** On the decision-ledger pattern (agent answers its own interview questions but records each one for audit): after roughly ten search phrasings, there is NO prior art for what the kit built. The field splits into two camps that do not overlap. Camp one makes the agent stop and ask a human (spec-kit's `[NEEDS CLARIFICATION]`, Kiro, Devin's confidence score, the DRR paper which explicitly forbids an agent finalizing its own decision). Camp two logs decisions after the fact with thin unstructured schemas and no confidence or reversibility fields (Addy Osmani's Automated Decision Log, Structured MADR, spec-writer's `[ASSUMPTION:]` tags). "Agent finalizes autonomously AND writes a structured override-ready record" is the gap. A 2026 paper, "Ask or Assume? Uncertainty-Aware Clarification-Seeking in Coding Agents" (SWE-bench Verified), explicitly names the missing logging half as an open problem. Publishable, or at minimum a strong til post.

## Per-repo notes

**gh-aw.** Workflows authored in plain Markdown, compiled by `gh aw compile` into hardened Actions YAML. The maintainers warn in their own docs that agentic workflows "require careful attention to security considerations and careful human supervision, and even then things can still go wrong", more honest than any other README here. Also has an MCP-gateway integrity filter that can drop content by author trust level below a configurable `min-integrity` threshold before the model sees it, and `gh aw logs` for per-run token/cost tracking. Sister framing: [GitHub Next Continuous AI](https://githubnext.com/projects/continuous-ai).

**Buildomator.** The GSD lineage is messy: the original GSD maintainer went unreachable in May 2026 and the associated Solana token was linked to a rug-pull; the community continuation is [open-gsd/get-shit-done-redux](https://github.com/open-gsd/get-shit-done-redux) (7.5k stars, MIT, no token references). The severity-routing behavior could NOT be confirmed in vanilla GSD Redux's own docs; it is documented in Buildomator specifically. GSD Redux's own contribution: wave-based execution where each executor starts with a clean 200k context while the orchestrator stays at 30-40 percent, plus a skill-frontmatter `effort:` field for per-skill token budgeting.

**aif-handoff.** Layer-aware execution computes dependency layers and dispatches parallel workers across worktrees, the same wavefront idea as `orchestrate.sh`. Two execution modes via `AGENT_USE_SUBAGENTS`. No decision or assumption log.

**agent-kanban.** Leader plans via `/ak-plan`, daemon polls, spawns one worker per task into a worktree, leader reviews and merges PRs, daemon auto-completes tasks on merge. Human-gated merge is the default posture, matching the kit's gated-final.

**OpenHands resolver.** Draft PR by default is the single best guardrail decision in the survey and costs nothing to adopt.

**SWE-agent.** Default output is a patch file the user applies; `--actions.open_pr` is opt-in with an explicit responsibility warning. Successor [mini-swe-agent](https://github.com/SWE-agent/mini-swe-agent) (6.2k stars) is ~100 lines, bash-only, each action a stateless `subprocess.run`, and scores over 74 percent on SWE-bench Verified. Worth 10 minutes as an argument that an elaborate tool interface may not be earning its keep.

**Aider watch mode.** Trigger comments are first-party developer input, so it sits outside the untrusted-content threat model, but it has no sandbox and edits the live working directory.

## Security-relevant lessons

**Prompt injection through untrusted text is the field's blind spot.** cyrus, open-swe, OpenHands, and Sweep all ingest human-written issue or PR text directly into agent context. Only gh-aw has a structural mitigation. OpenHands is the cautionary tale with receipts: CVE-2026-33718 (command injection), plus two published attack chains from Embrace The Red ("OpenHands and the Lethal Trifecta", prompt injection to access-token exfiltration; "ZombAI", prompt injection to RCE via the CLI). OpenHands' own mitigation post concedes their defenses rely on "fuzzy, non-deterministic" model behavior rather than hard guarantees. Direct read-across to this kit: a `#auto` row's free-text Notes cell is untrusted input the moment anyone but the operator can edit the board, and the same holds for any issue body the loop later ingests. The pointer path is hardened; the prose path is not.

**Runaway-loop protection is inconsistent and mostly absent.** Only aif-handoff (convergence detection), Buildomator (severity routing), and frankbria/ralph-claude-code (five distinct circuit breakers) have documented stop-and-hand-back mechanisms. Backlog.md, kanban-md, Task Master, kanban-code, and vanilla GSD Redux have no iteration cap at all. ghuntley's canonical `loop.sh` defaults `MAX_ITERATIONS=0` (infinite), has no locking, and does not halt on push failure.

**Cost blowout is structural, not policed.** Only three projects enforce a real spend ceiling: SWE-agent (`per_instance_cost_limit` / `total_cost_limit`), vercel-labs/ralph-loop-agent (`costIs(maxCost)` with pricing tables), frankbria/ralph-claude-code (100 API calls/hour). Everyone else offers efficiency claims instead of caps. The kit's `--max N` bounds rows per run, the right axis for the watcher, but a single row that goes pathological is still unbounded.

**Two cheap wins.** Draft-PR-by-default (OpenHands) and auto-expiring claim leases (kanban-md's 1h `claim_timeout`, claimed files read-only on Unix) are both small diffs against what already exists.

## Caveats

Star counts are from live GitHub page fetches at survey time. Last-commit dates were not exposed for most repos and are marked unknown rather than guessed. "Not documented" means absent from the fetched README/docs, not confirmed-absent. Two claims flagged unconfirmed: GSD Redux's severity routing (documented only in Buildomator) and cyrus's trigger mechanism.
