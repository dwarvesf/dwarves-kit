## Method

1. Enumerate the live dirs by `ls`, never by trusting a doc's inventory count: `ls commands/*.md agents/*.md skills/*/SKILL.md hooks/*.sh`. At generation time: 34 commands, 26 agents, 7 skills, 25 hooks (92 features total).
2. Per COMMAND: trigger = human types it, or Claude infers intent from `$ARGUMENTS`/context (frontmatter `disable-model-invocation: true` = human-only, only `wayfind` has this today); runner = the command's own prompt; hand-offs = agents it dispatches (`grep -l <agent-name> commands/*.md`) and the next command in the lifecycle chain.
3. Per AGENT: trigger = dispatching command(s), read from the authoritative `README.md` "Agents ... Dispatched by" table (cross-checked against `grep -l <agent> commands/*.md`); write-capable vs read-only from its frontmatter `tools:` line.
4. Per SKILL: trigger = auto-fire on description match (`disable-model-invocation` absent/false) vs explicit user invocation; read each `skills/*/SKILL.md` frontmatter description.
5. Per HOOK: trigger = its event, read from `hooks/hooks.json` (plugin path) / root `settings.json` (bash-install path, same wiring); blocking (hard, exit 2) vs advisory (exit 0 + message) vs convenience (never blocks), per `docs/architecture.md`'s hook inventory table.
6. Cross-check against `docs/architecture.md`'s V-phase inventory (60 = 34 commands + 26 agents) for phase placement; live files win on existence over any doc claim. `README.md`'s own "Dispatched by" / "Skill" tables were live-authoritative and used directly for agent/skill trigger columns rather than re-deriving from scratch.

Coverage-gap check: for each feature, `grep -rl <name> docs/specs/*.md` and `grep -rl <name> tests/*.sh`; zero hits on either side is a gap (substring match, so a hit count only ever undercounts, never fabricates).
