# Pitfalls: generalizing /kit:gauntlet into a preset-driven probe-convergence engine

1. `lib/config/kit-config.sh:96-114` (selftest), the security-bearing key `gauntlet.runner_host` is read via a ROOT-ONLY accessor (`kit_config_get_root`) that must ignore project `.kit.toml` overrides. A per-preset config shape (`[gauntlet.onboarding]`) changes the dotted-key path this test hardcodes. Spec must say: `runner_host`/`probe_key_ref` stay root-only-readable under whatever key shape presets use, and the selftest is updated in the same commit, not after.
2. `lib/config/module-registry.md:52`, states the literal keys `gauntlet.runner_host` / `gauntlet.probe_key_ref`. A preset-nested key scheme desyncs this doc from `kit-config.sh` silently (no test cross-checks the two). Spec must update both in one commit.
3. `kit.toml` `[gauntlet]` section, one global `runner_host`/`probe_key_ref` shared by every gauntlet run today. Spec must decide explicitly: one pair for all presets, or per-preset pairs (a HOST-only preset may need a different runner/key than a repo preset), silence here means the generalized engine inherits an implicit "all presets share one runner" assumption.
4. `commands/gauntlet.md` rules 2/7/8 + `docs/patterns/gauntlet.md` limits 4/5, the ONLY places stating probe-safety invariants (spend-capped key only, no answer key in room, scrub transcripts, mid-tier probe). Grep of `docs/` and `skills/` outside these two files found zero other mentions. Spec must put these invariants in the shared/generic engine doc, not leave them to be re-stated (and drift) per preset file.
5. `tests/gauntlet/cleanroom/run.sh` + `Dockerfile`, the clean-room recipe is git/npm-shaped (`git archive HEAD`, `node:22-slim`, `npm install -g @anthropic-ai/claude-code`, git config for probe commits). A non-code artifact (a runbook, an SOP) has no git repo to archive and may need a HOST/service snapshot, not a Docker image built from source. Spec must define the clean-room abstraction per artifact-kind, never assume `git archive` is universal.
6. `tests/gauntlet/check-submission-user.sh:1-25`, the submission checker takes a `<fixture-repo>` arg and implicitly assumes a patch/PR shape. A non-code outcome contract (e.g. "the on-call engineer followed the runbook and the service recovered") has no patch to check. Spec must generalize "submission checker" to any deterministic oracle over the outcome contract.
7. `docs/patterns/gauntlet.md` limits 4 and 8 get WORSE under generalization: a host-based probe (not a fresh container) has far more ambient state to leak the answer key from than "exclude one git path from the archive," and "clean room ≠ contributor's machine" becomes "clean room ≠ the real HOST" for infra/runbook presets, a bigger gap. Spec must restate the mitigation per artifact kind, not inherit the git-archive-specific fix.
8. `tests/test-meta.sh:706-710,2972-2973`, the literal `[[QL-VERDICT` marker is pinned ONLY for `test-plan-review-team.md` and `ui-design.md`; nothing pins `gauntlet.md` today, so renaming the marker there breaks no test. But SPEC-226's "observe needs no change" claim assumes the marker grammar is IDENTICAL across every emitter. If presets vary the marker shape, future observe wiring breaks silently with no test to catch it. Spec must keep the marker preset-invariant or add test-meta coverage for gauntlet's own emission.
9. `docs/specs/SPEC-226-gauntlet-telemetry-learning.md:25-27`, the gate-ledger phase name passed is the literal string `gauntlet` (never "onboarding"), safe today. Generalization must pick: one shared phase name for all presets (dashboards can't distinguish which preset ran) or a namespaced phase (`gauntlet:onboarding`), which changes `normalize_phase` behavior and any stats grouped by exact phase string.
10. `docs/FEATURES.md:27` is machine-generated from `commands/gauntlet.md`'s frontmatter `description:` (currently "Onboarding gauntlet: ..."); test-meta's freshness gate (`lib/registry/feature-registry.sh generate`) forces a regen after any description edit. But `docs/workflow-paths.md` currently has ZERO "gauntlet" line even though topology-drift's own contract requires one path-index line per registry row, gauntlet is ALREADY undetected drift. Adding preset complexity on top of this gap ships with no audit safety net until the baseline row is added.
11. `tests/gauntlet/README.md` (SPEC-227 scenario pack), `scenarios.md` / `make-card.sh <ROW>` and the campaign shape (J1-J11) are onboarding-specific. Spec must decide whether the scenario-pack/campaign machinery becomes generic-engine-level (needs a preset parameter, absent today) or stays an onboarding-preset-only add-on.
12. `tests/gauntlet/deploy/mini.gauntlet-campaign.plist`, a live launchd job invokes the onboarding-only campaign runner directly. Renaming or reshaping the Inputs table in `commands/gauntlet.md:23-36` (input names, defaults) risks silently breaking this deploy artifact; no test covers deploy plists. Spec must call out this consumer explicitly for a compat check before merge.
