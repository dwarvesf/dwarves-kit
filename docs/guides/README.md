# User guides

Task-oriented guides for people USING the kit on their repos. Each answers "what
do I do and what will I see", nothing else. The contracts live in `WORKFLOW.md`,
the rationale in `PHILOSOPHY.md`, per-command reference in `MANUAL.md`; a guide
never overrides those, it translates them.

| Guide | Read it when |
|---|---|
| [gauntlet.md](gauntlet.md) | you are about to let outside devs into a repo, or just rewrote its contributor docs |
| [mega-goal.md](mega-goal.md) | your ask is one destination reached through several dependent pieces of work |
| [v-model.md](v-model.md) | you wonder why the kit keeps testing at every altitude, or why "all tasks green" still failed acceptance |
| [loops.md](loops.md) | a command reported a round cap, an honest halt, or a verdict like SOLID / REVISE / RECONSIDER and you want to know what to do |

Convention for new guides: user voice, second person, one diagram maximum, a
"what you do" per outcome, and a short common-questions tail. Name the file
after the topic, add a row here.
