# User guides

Task-oriented guides for people USING the kit on their repos. Each answers "what
do I do and what will I see", nothing else. The contracts live in `WORKFLOW.md`,
the rationale in `PHILOSOPHY.md`, per-command reference in `MANUAL.md`; a guide
never overrides those, it translates them.

## The flow

| Guide | Read it when |
|---|---|
| [spine.md](spine.md) | you want the map: what comes after what, from "what should I do" to shipped |
| [lanes.md](lanes.md) | you wonder why a small change got big ceremony, or vice versa |
| [grill.md](grill.md) | the kit starts interviewing you before working |
| [autonomy.md](autonomy.md) | you want it to check in more, or less |

## The engines

| Guide | Read it when |
|---|---|
| [loops.md](loops.md) | a command reported a round cap, an honest halt, or SOLID / REVISE / RECONSIDER |
| [debug.md](debug.md) | you said "fix this bug" and it went hunting for a root cause instead |
| [dispatch-vs-mega.md](dispatch-vs-mega.md) | your work is several pieces and you are unsure how they run |
| [mega-goal.md](mega-goal.md) | your ask is one destination reached through several dependent pieces |

## The checks

| Guide | Read it when |
|---|---|
| [v-model.md](v-model.md) | you wonder why the kit tests at every altitude, or why all-green tasks still failed acceptance |
| [gates-and-proof.md](gates-and-proof.md) | something BLOCKED (ship gate, proof of done, iron law) and you want the way through |
| [review.md](review.md) | you got a SHIP / FIX THEN SHIP / DO NOT SHIP verdict |
| [gauntlet.md](gauntlet.md) | you are about to let outside devs into a repo, or just rewrote its contributor docs |

Convention for new guides: user voice, second person, one diagram per guide,
a "what you do" per outcome, and a short common-questions tail. Name the file
after the topic, add a row here in the right group.
