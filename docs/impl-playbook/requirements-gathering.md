# Requirements gathering rules

Distills Amazon's Working Backwards PR/FAQ method plus a lightweight pre-build question checklist. Lightweight, for solo/small-scale work, not a BABOK-style enterprise process.

## Before building anything non-trivial, answer
- What is the real problem, and who has it?
- How often does it happen, and what does it cost them not to have this solved?
- What is the one measurable success outcome?
- Write a 3-5 line mock announcement of the finished thing (the PR/FAQ trick). If it is hard to write a believable announcement, the problem or solution is not yet clear enough to build.

## When to go further
Only sequence into a full user story map (Jeff Patton) when the build has multiple distinct user journeys worth ordering into a walking skeleton. For a single-journey build, the questions above are enough. Do not add ceremony the size of the project does not need.
