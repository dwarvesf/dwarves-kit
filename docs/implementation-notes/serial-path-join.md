# serial-path-join: implementation notes

Spec: `docs/specs/SPEC-421-tiered-verification.md` rule 4 (serial path joins per DAG level). Follow-up to implementation note D9 of `tiered-verification.md`. Only deltas from the spec.

## Delta

- S1. The spec says the serial join runs "once per DAG level" and the wave join runs before the merge. The serial loop has no conductor-side merge: each worker merges its own PR through `mega-merge.sh`. So the serial join cannot pin a pre-merge head. It runs after the level's merges, on the base tree, and gates the next level. A red level is already on the base; the join stops the run from building the next level on it. Open for the operator: a join that holds the level's merges back needs the workers to stop merging in tiered mode, which changes the worker prompt and how the box is grounded.
- S2. The wave join compares a base run with a merged run. The serial join has no pre-level tree to run, so it judges one run against the lead's committed known-failures list (`known-failures.sh classify` with no `--known-from`). A crash with no parsed failure is red. The executed count may not drop below the last green level's (`--prev-count`, read from the `join-level-<n>.ok` markers); level 0 has no floor, and no `--base-count` exists.
- S3. Level = 0 with no `depends`, else 1 + the deepest dependency, computed as a fixpoint table over the whole ROADMAP (`_sg_levels`, awk), so a cycle or a dense DAG ends in at most n+1 passes. A level is due when every sub-goal at that level or a lower one is checked and it has no `.orchestrate/join-level-<n>.ok`; due levels join in ascending order. The serial pick is ROADMAP order and ignores `depends`, so a dependent listed first runs first; its level still waits for the lower ones.
- S4. The check runs at the top of every `cmd_run` cycle, before any dispatch, not after a sub-goal completes. That makes a red halt survive a re-run (the level has no marker, so it joins again before anything dispatches) and joins a level a `gate` sub-goal closed after a human merge. `[mega] verify`, `join_cmd` and the `[test]` keys are read once per run, at the base sha pinned on the first cycle, before the first dispatch, so no worker's merge can change the bar. `classify`, `names` and `read` use that sha too. The suite itself runs on the current base tree. A run outside a git repo skips the join; with `verify = "off"` the cost is one config read.
- S5. A tiered run with no `[test] join_cmd` at the pinned base halts at the first due level. An unresolvable base falls back to HEAD the way `_verify_base` does; the wave path's fail-closed stop on an unreadable base is not copied for the config read.
- S6. The join needs origin's current tip: after `_verify_base` it compares the base sha with `git ls-remote origin` and halts when they differ or origin is unreachable, because `_kit_mc_base_ref` swallows a failed fetch and a green on a stale ref proves nothing. Only a `refs/remotes/origin/*` base is checked.
- S7. The join reuses `_join_run` (scrubbed environment, background run), `_wave_join_cleanup`, `_wave_join_interrupted` (a `_JOIN_LEVEL` switch picks its wording) and `known-failures.sh`. It does not reuse `_wave_join` or `_wave_join_run`, which are built around pinned PR heads and a second merged tree. The traps stay installed from before the temp dir exists until after cleanup.
- S8. Reviewed and not changed, open for the operator: (a) a `per-pr-review` merge posture leaves a level's PRs unmerged, so the base lacks the work and the join tests main without it; the join does not check that a level's PRs landed. (b) In a mixed run (`WAVE_CAP` of 2 or more with serial fallthrough) a level the wave join already covered is joined again by the serial check, since the wave path writes no marker: extra time, not a correctness gap. (c) Interrupting a join signals the suite's direct children only (`pkill -P`), the same as the wave join, so a grandchild can outlive it. (d) The join command runs with the conductor's environment except the `KIT_*` and ledger variables the wave join already scrubs.
