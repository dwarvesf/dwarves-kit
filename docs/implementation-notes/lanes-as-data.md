| 12 | Review round: the floor is single-pass. Paths come from `diff -z --raw` with `core.quotePath=false`, matched once per kind with `grep -f`, and added lines go through one awk pass. 1000 paths with 20000 added lines run in about 0.3 s. The ship-gate hook timeout is 30 s in `hooks/hooks.json` and `settings.json`. |
| 13 | Spec-less floor hits now BLOCK (reverses the earlier warn-only decision, lead-approved). The spec text (AC19, DEC-8, edge case 3, TASK-6) is amended. |
| 14 | The ship-gate skips only when the push TARGET is the default branch. It recognizes `git -C`, `git -c`, matches `--force` and `-f` exactly, resolves the base from `origin/HEAD` (a repo with no origin falls back to local main or master), and diffs the pushed ref. The proof gate's own `proof-ledger.sh check` still diffs HEAD internally; that is pre-existing and untouched. |
| 15 | New hard-path kinds: `infra` (Dockerfile, IAM terraform) and `submodule` (gitlink). `.github/` counts whole. The floor reads the kit root lane data only, never the operator overlay. An override that empties a lane with required gates is ignored, and only the five kit lane names resolve. |
| 16 | `lane-classify.sh risk` returns `full` when the lane is full or a full suggestion fired. significance-classify, orchestrate, harvest_sweep, and `commands/wrap.md` use it because keyword hits only suggest now. `proof-gate.sh` and `dispatch.md` keep `classify`: they never compared it to `full`. |
| 17 | The tracked-and-clean test and the `git show <rev>:.kit.toml` read live once in `lib/config/kit-config.sh`. `.kit.toml` uses `^kit[.]toml$` because a backslash in a TOML basic string is invalid. The default test run now lists every case; earlier additions had dropped out of the list silently. |
| 18 | Second review round: the parser arms race ends in FAIL CLOSED. `lib/gate/push-refs.sh` reads every `git push` segment and `gh pr create --head` in the command and reports REF, DEFAULT, FORCE, or BLOCK. The hook blocks on `--all`, `--mirror`, `--tags`, `--follow-tags`, `--delete`, an option it does not understand (including `--git-dir path`), a variable or command substitution in a push segment, a wrapper (xargs, sudo, bash -c), a source that does not resolve with `rev-parse ^{commit}`, and more than one branch ("push one branch at a time"). It applies only in an adopted repo whose default branch has `lane_gates = true`. |
| 19 | The structural fix is a native git pre-push hook: git hands it the exact refs on stdin, so nothing has to be parsed from a shell string. This PreToolUse parser is best-effort and fails closed until that hook exists. |
| 20 | The floor scan pins every git call: no color, no external diff, no textconv, `--text` (a committed `-diff` attribute cannot hide a file), fixed `a/` `b/` prefixes, no attributes file. `+++` counts as a header only between `diff --git` and the first `@@`. The `-z` stream is split in one awk pass (30000 files in about 2 s). The where test reads the code line at a word boundary. |
| 21 | `[lanes] default = "tiny"` is refused (falls back to normal). `orchestrate.sh` records the `classify` lane at START and logs the full suggestion against the run through `--rid`. The `toml-valid` case prints a visible SKIP when `tomllib` is missing. |
| 22 | Final round: parser markers start with `@@` and the hook matches whole lines (a branch named DEFAULT or FORCE no longer passes for a marker). `safety-gate.sh` blocks combined short flags carrying f (`-fu`, `-uf`) and reads the destination of every refspec (`feat/x:refs/heads/main`, `:refs/heads/master`). Both hooks join backslash-newline continuations before splitting. A heredoc or here-string fed to bash, sh, or zsh whose body pushes is refused. The adoption marker is read at the default branch, not the working tree. |
| 23 | The spec gained a `## Threat model`: the gates guard a cooperative agent against skipped steps, not an adversary. Residual risks and the structural next step (a native pre-push hook installed by adopt, then server-side required CI) are listed there. |
