- `cmd_sync` reads `multica_token_ref` and calls `secret-cache-read` or `op read` on every sync whose operator config sets the ref, whether or not Multica is a named app. Keep that; narrowing it is a follow-up.

- Filter keys for a hyphenated app use underscores in the config key and keep the hyphen in the filter token (`notion_taskboard_only_tags` becomes `--filter notion-taskboard:only_tags=...`).
- `HermesSource` is the only source that takes `body_expander`; `ctx.hooks.get("body_expander")` is `None` when no adapter declares the hook, and a declared hook that fails to import must exit non-zero.
- `sync_core` is imported by `board_add.py`, `backlog.sh`, `bin/add-backlog` and `lib/reflect/staging-format.py`; `insert_inbox_rows` and `plan_create_only` gain optional parameters only.

## The loader and the bash reader (TASK-B): what the next builder must know

## TASK-J2 (sweep legs, harden): what the next builder must know

- Missing script: `run_leg` checks `[ -f script ]` when the leg is due, prints `  leg <name> failed: <absolute script path> not found`, records the `mirror` fallback (`leg mirror failed: ... not found`, rc 1) for the leg named `mirror` only, sets `rc_any=1` and goes on to the next leg. - Signals: the runner sets `trap 'leg_signal 130' INT` and `'leg_signal 143' TERM` only while a leg runs and resets them after. The handler ignores both signals, sends TERM to the leg, `wait`s for it and exits. A background child of a non-interactive bash ignores INT, so INT also reaches the leg as TERM; the leg's own TERM trap (`legs/mirror.sh`) runs when its foreground command returns, so a signal during `board mirror` ends the sweep only after that `board mirror` call returns (the same deferral the old inline trap had). Bash also runs a leg's EXIT trap when TERM kills it with no TERM trap, so the origin-copy cleanup does not depend on the TERM line; the TERM trap makes the exit code 143.
