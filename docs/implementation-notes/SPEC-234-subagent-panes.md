Context: work runs from an ops-toolkit-cwd session via a hand-made worktree, so the
interactive `/kit:spec` -> `/kit:spec-validate` command flow was replaced by: Fable
authors the spec directly from a read-only scout report, then dispatches validate

Impact: none on artifacts; process-only substitution.

## 2026-08-28 12:55 Spec rev 2 after the validate lenses; two findings changed the interface

Context: the advisor lens falsified two spec claims by experiment/code-read: bare `jq`
aborts on a malformed input line (rc=5, verified), and the conductor cannot name
`agent-<id>.jsonl` paths at dispatch time (Agent tool returns no path), which made rev 1
unreachable as specified.
Decision: rev 2 adopts `jq -R` + `fromjson? // empty`, adds directory targets and a
`--latest` session-dir derivation (DEC-007), moves the formatter seam from env to argv
(env does not cross the tmux server boundary), fires viewer push only on session
creation, and flips the rc contract to always-0.
Why: each is in the spec now with its finding number; this note exists so future-you
knows rev 1's shape was WRONG in ways tests would have gone green on (the env-seam
false-green in particular).
Impact: interface grew (`<target>` = path | dir | --latest); no scope growth beyond it.
Open questions for the operator: the `--latest` slug derivation copies the harness's
observed naming (`/` and `.` -> `-`); if the harness ever changes its project-dir
naming, DEC-007's helper silently derives a non-existent dir (fails as a clean skip).

## 2026-08-28 12:58 Spec file briefly contained literal control bytes

Context: writing the security section embedded real ESC/C1 bytes into the markdown

Why logged: the same hazard class the spec is about; a reminder that fixture files for

## 2026-08-28 13:40 `viz`'s spec-literal `\uNNNN` char class does not strip control bytes

Context: implementing `def viz: gsub("[\\u0000-\\u0008\\u000b-\\u001f\\u007f-\\u009f]"; "");`
verbatim and testing it against `"hello world"` stripped letters ("hello world" ->
" w"), not control bytes -- jq 1.8.2 (Oniguruma) does not parse `\uNNNN` as a
single-codepoint escape inside a bracket expression the way the spec's text assumes;
`\uHHHH-\uHHHH` inside `[...]` silently falls back to some other range parse instead
of erroring, so the bug is invisible until you check the output.
Decision: replaced with a codepoint filter on `explode`/`implode` (same C0/C1 ranges,
same tab/newline survival), no regex escape involved.
Why: the spec's own security intent (strip ESC/OSC-52 before it reaches the
operator's terminal) has to actually hold; a literal-but-broken implementation would
ship a formatter that silently does NOT strip control bytes, defeating H1.
Impact: `pane-tail.jq`'s `viz` def differs from the spec's literal text; behavior
(what gets stripped, what survives) is identical to what the spec specifies.
Open questions: none -- verified against the exact fixture (ESC + OSC-52 BEL
sequence) T6 exercises.

## 2026-08-28 14:20 Real-tmux verification: name-based capture-pane targets the wrong window

Context: running the spec's required real-tmux-server behavioral check (`panes` spawn +
`capture-pane -p` + append + reverify, plus the formatter-swap negative control), manual
`tmux capture-pane -t <session>:<window-name>` and `list-panes -t <session>:<window-name>`
resolved to the WRONG window (the `_init` placeholder, not `sa-<id>`) on this machine's
tmux 3.7c, even though `list-windows` showed the name correctly assigned. `<session>:<index>`
(numeric) targeted correctly every time; `ps`-tracing each pane's pid confirmed the real
`_pane-tail` process (with `tail -F` + `jq` children) was always running under the CORRECT
window regardless of how it was addressed.
Decision: none needed in the shipped code -- `cmd_panes` itself only ever targets
`kill-window`/`new-window` by name for its own idempotent create/replace pairing (never reads
state back via a name-based target), so this quirk is confined to ad hoc manual verification
commands, not a code path the feature exercises.
Why logged: saves a future verifier from chasing a phantom bug when a manual `capture-pane
-t session:name` check looks wrong; use the numeric index instead.
Impact: none on the shipped feature; the proof-of-done's behavioral transcript notes this and
uses numeric targeting.
Open questions: none.
