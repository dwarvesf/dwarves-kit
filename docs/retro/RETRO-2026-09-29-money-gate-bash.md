## Metrics
- Validation rounds: 2 (NEEDS REVISION, then APPROVED with critical=0)
- Goldens: 59, generated from the Python shim before the port, plus 1 added after a vacuous negative control

## What worked
- Frozen goldens from the Python shim, generated by the orchestrator before the implementer started. The port could not fit the test to itself.
- The validator benchmarked latency under load instead of trusting a clean number, and that is the only reason the timeout trap at 100 KB surfaced in round 1 instead of shipping quiet.
- A fresh review replaying 18 realistic payloads and 1,000 fuzz cases against the Python hook, with 0 mismatches on both.

## What hurt
- NC1 passed vacuously on its first run: the corpus had no golden with a variant term embedded inside a longer word, so dropping the left-boundary check changed nothing observable. The gap was a corpus hole, not a scanner bug, and only the negative control step caught it.
- The `HOME`-unset `set -u` trap (losing the strict ask when `HOME` is unset) was invisible to the implementer's own test pass and was found only by a fresh review reading the script cold.
- Devin's headless run timed out at 1 hour with the port done but the doc pass unstarted, costing a resume cycle.
