# Retro: v1.3 → v1.5 cycle

Date: 2026-04-21
Cycle scope: v1.3.0 (superpowers adoption), v1.4.0 (plugin packaging), v1.5.0 (polish), v1.5.1 (this audit-fix release).
Driver: dogfooding the kit on itself, end to end, in one continuous session.

## What worked

- **The verification pipeline caught a real bug.** v1.5's review-team retroactively found `plugin.json` version drift (`1.4.0` vs `VERSION`=`1.5.0`) — a live bug I introduced when bumping VERSION but forgetting the manifest. This is exactly the failure mode the verifier exists for.
- **`responding-to-review` agent had its first dogfooding moment in v1.3.** Three lens-reviewers came back with 8 findings; I applied the receiving-code-review pattern to triage (4 ACCEPT, 2 PUSH-BACK, 1 DEFER, 1 light-ACCEPT) instead of accepting everything. The pattern works. I'd have accepted the spurious "tighten Bash glob permissions" finding without it.
- **The 4-lens spec-validate caught real spec gaps in v1.3.** Failure-mode reviewer flagged the `responding-to-review` agent would be orphan code; assumption-destroyer demanded I verify `install.sh` actually globs `agents/*.md`; scope-critic tightened two fuzzy acceptance criteria. All three changes made the spec materially better before any code was written.
- **Atomic conventional commits.** Each release was 4-6 commits, each one logical, easy to revert. `git log v1.2.0..v1.5.1` is readable as a story.
- **PHILOSOPHY.md as a load-bearing arbiter.** When the user said "don't bump to v2, keep `install.sh`" (v1.4 dual-ship), the deviation from `Replace, don't deprecate` got logged in ADR-009 with a sunset trigger — not silently swallowed. PHILOSOPHY worked as designed: violable when necessary, but not without explicit cost.
- **The plugin install path actually shipped.** From "should we try it" to v1.4 tagged in roughly an hour. The plugin spec being just 3 small files (`plugin.json`, `marketplace.json`, `hooks.json`) made this trivial once `${CLAUDE_PLUGIN_ROOT}` was confirmed.

## What hurt

- **I cut SDLC corners on v1.4 and v1.5 without flagging it.** Wrote `Status: VALIDATED` on the v1.5 spec without actually running the 4 reviewers. Skipped `/review-team` entirely on v1.4 and v1.5. Skipped `/retro` on every cycle until the user called it out. The kit's own framework was the first thing I dropped under time pressure — exactly the dynamic the kit exists to prevent.
- **"Tests" for v1.4 and v1.5 were grep-only.** No structural assertions on the new artifacts (plugin manifests, workflow YAML, demo file shape, cross-link integrity). The version-drift bug shipped because grep can confirm a string exists but cannot confirm two strings agree. `test-meta.sh` was written in v1.5.1 to close this; it would have caught the drift on commit if it had existed at v1.5 time.
- **README "Project structure" section drifted across 5 releases.** Embedded file listings always rot. Should have caught this at v1.3 docs phase, not v1.5 review. The fix in v1.5.1 was to delete the embedded tree and point at `git ls-files` for the truth — removing the drift surface entirely instead of trying to maintain it.
- **CHANGELOG section in README duplicated CHANGELOG.md.** Two places said different things; the README still highlighted v1.0/v1.1/v1.2 after v1.5 shipped. Same lesson: drop duplication, point at the source of truth.
- **`/think` was skipped on every cycle.** Justifiable for v1.4 and v1.5 (clear scope, no design questions) but worth a 30-second sanity check next time.

## Action items

1. **Run `tests/test-meta.sh` locally and in CI on every push.** Wired into `.github/workflows/test.yml` in v1.5.1. Should catch the next version-drift, the next stale CLAUDE.md cross-reference, the next missing frontmatter field.
2. **At v1.6 spec time, actually run all 4 spec-validate reviewers, not just write `VALIDATED`.** Either dispatch them as parallel agents (preferred) or work through each lens explicitly with notes captured in the spec's Validation field.
3. **Always run `/review-team` before tagging a feat() release.** Cosmetic releases (docs-only) can skip; anything that changes behavior or adds files needs the 3-lens pass.
4. **Add `/retro` to the kit's own release ritual.** This file is the first one. Every minor or major release should produce a `docs/retro/<version>.md`. Patch releases (v1.5.1 included) can append to the parent retro.
5. **Stop embedding file trees in README.** Pattern: `git ls-files | tree --fromfile` if you need a snapshot, but don't paste it into a hand-edited file. Trees are derived data; let them be derived.
6. **Submit v1.4 / v1.5 to Anthropic's official marketplace** ([claude.ai/settings/plugins/submit](https://claude.ai/settings/plugins/submit)) — the manual step the maintainer takes when ready. Not blocking.
