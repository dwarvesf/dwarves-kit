# The ledger-event schema

The canonical, read-only contract `ledger-observatory` (SG-02's ETL onward) reads
against. This doc **names** an existing convention already live in
`~/.claude/dwarves-kit/lib/gate-ledger.sh`; it invents nothing. Every claim below is
backed by a real grep against live files, not memory (see `## Inventory`).

## The universal envelope

Every kit log line, across every store in the inventory below, starts:

```
<ISO8601 UTC timestamp> | <field> | <field> ...
```

- **Timestamp:** `YYYY-MM-DDTHH:MM:SSZ` (UTC, trailing `Z`), produced by each writer's
  own `now()` helper (`date -u +%Y-%m-%dT%H:%M:%SZ` or equivalent).
- **Delimiter:** ` | ` (pipe, padded with one space each side).
- **Append-only:** every store below is written with `>>`; nothing rewrites a prior line.

This envelope is what makes every store below genuinely readable by one generic
pipe-log reader (first field is always a timestamp, split on ` | ` for the rest), the
ROADMAP's binding "one pipe-log reader drains the whole schema-uniform kit corpus"
claim. It does **not** by itself mean every store's remaining fields share one grammar;
see the two tiers below.

## Tier A: the canonical ledger-event marker (strict, this is THE schema)

Produced exclusively by `lib/gate-ledger.sh`, one file per run-id under
`~/.local/state/dwarves-kit/logs/runs/<rid>.log`. This is the schema 02's ETL targets
for structured querying (lane telemetry, gate audit, token cost, understanding debt), `lib/lane-telemetry.sh`'s own header comment names exactly this format as what it
consumes. Every line:

```
<ISO8601> | <VERB> | <payload>
```

`VERB` is one of exactly 6 values. Each has its own payload grammar, **not** all of
them are `k=v`; this table states plainly which are and which aren't:

| Verb | Payload grammar | k=v? | Producer |
|---|---|---|---|
| `START` | `lane=<L> classified=<L> type=<T> [ctype=<T>] repo=<R>` | yes, space-separated | `gate-ledger.sh start` |
| `START-AMEND` | same as `START` | yes | `gate-ledger.sh start --amend` |
| `GATE` | `<phase> \| <ran\|skipped\|override> \| <reason>` | **no**, 3 more pipe-delimited positional fields, not k=v | `gate-ledger.sh record` / `override` |
| `ACTION` | freeform oneline text | **no**, opaque text | `gate-ledger.sh action` |
| `TOKENS` | `in=<N> out=<N> cache_read=<N> cache_create=<N> [cost=<N>] [phase=<P>]` | yes, space-separated | `gate-ledger.sh tokens` |
| `DEBT` | `significance=<low\|high> worthiness=<low\|high> verdict=<tap\|wave\|not-significant> [response=<engage\|defer\|wave>] [reason=<text>]` | yes, space-separated (see Edge Cases) | `gate-ledger.sh debt` / `debt-response` |

**Parse rule:** split each line on ` | ` for the first two delimiters
(`timestamp`, `verb`); everything after the second delimiter is the payload, parsed per
the verb's own grammar above, `GATE`'s payload itself contains further ` | `
delimiters (positional, not part of the k=v tiers), so a generic parser must not assume
"payload = the 3rd field only."

## Planned markers conform on arrival

The mega-goal's two not-yet-emitting ledgers are **already implemented** by
`gate-ledger.sh` as `DEBT` and `TOKENS` verbs (see table above); their producing
features (understanding-gate SG-02's debt-tracking, kit-face SG-03's token-cost UI)
have not yet called them in anger, but the marker shape itself already exists and is
already exercised by the kit's own test suite (`tests/test-*.sh` in `dwarves-kit`
invoke `gate-ledger.sh debt`/`tokens` directly). **No adapter, no code change, and no
future schema revision is needed for either to conform**, this is what "SG-01 does not
wait for them to exist" (ROADMAP) means concretely.

## Tier B: kit context/hook logs (loose envelope only, informational)

8 standalone files, each written by one hook script, under
`~/.local/state/dwarves-kit/logs/*.log` (sibling to the `runs/` directory, not inside
it). All 8 satisfy the universal envelope (timestamp-prefixed, pipe-delimited,
append-only) but **do not** share Tier A's `VERB` enum or payload grammar, each hook
defined its own field layout independently. They are named here for completeness (part
of the goal's "confirm the ~10 existing kit stores... conform", conform at the
envelope level) but are **out of scope** for `ledger-observatory`'s structured queries;
02+ read Tier A only. Real samples, one per file (all times 2026-07-02/03, from live
logs on this machine):

| File | Real sample (verbatim, truncated) | 2nd-field shape |
|---|---|---|
| `commit-format.log` | `... \| BLOCKED \| subject is 475 chars (max 72). \| $(cat <<'EOF' ...` | verb-like (`BLOCKED`), but the trailing field can embed a raw multi-line heredoc, **not guaranteed single-line** (see Edge Cases) |
| `completeness.log` | `... \| LANE-CHECK \| downgrade \| chosen=tiny suggested=full \| add user authentication...` | verb-like (`LANE-CHECK`), 4 total fields |
| `mega-merge.log` | `... \| somerid \| DRY-RUN merge pr=1 lane=full posture=auto-to-final` | **not** a verb, 2nd field is a run-id; 3rd field is freeform |
| `proof-overrides.log` | `... \| /Users/me/ws/repo \| drop-projects-dir \| OVERRIDE \| docs/layout-only: fold homelab-net-research...` | repo-scoped (ID-299): 2nd field is the repo root path, 3rd the slug, 4th the verb-like `OVERRIDE`; pre-ID-299 entries omit the repo field |
| `safety-gate.log` | `... \| BLOCKED \| rm-rf \| /Users/.../ops-toolkit \| cd /tmp && export ...` | verb-like (`BLOCKED`), trailing field can embed a raw shell command (may itself contain `\|`) |
| `ship-gate.log` | `... \| BLOCKED \| proof-gate \| rtk-611-update` | verb-like (`BLOCKED`), 3 total fields |
| `slop-cleaner.log` | `... \| SLOP \| 7 files \| /Users/.../ops-toolkit` | verb-like (`SLOP`), 3 total fields |
| `spec-drift-guard.log` | `... \| DRIFT \| /path/one \| /path/two` | verb-like (`DRIFT`), 3 total fields |

Honest count: **9 kit log stores** identified by direct inventory (8 standalone +
1 per-run-ledger convention covering 68 live `<rid>.log` files), the ROADMAP's "~10"
is this same set, approximated. This doc does not force a rounder number than what a
real `find`/`grep` sweep produced.

## Edge cases (binding for the conformance check and for 02's ETL)

1. **`GATE`'s reason field may itself contain `|`.** `oneline()` in `gate-ledger.sh`
   strips parentheticals and collapses newlines to spaces, but does not strip `|`. A
   parser must split on the FIRST two ` | ` delimiters only (timestamp, verb), then
   treat the rest of the line as `GATE`'s own `phase | state | reason`, where `reason`
   itself is the tail-most text and may contain further unescaped `|` characters.
2. **`DEBT`'s `reason=` value has `=` neutered to `:`** by the producer itself (a
   documented security guard in `gate-ledger.sh`, so a value can't smuggle a fake
   `key=value` token). A parser must not assume a raw `=` never appears in a payload's
   free-text tail elsewhere (it does, in `ACTION` and `GATE`'s reason).
3. **Tier B's trailing fields are not guaranteed single-line.** `commit-format.log` and
   `safety-gate.log` samples above show a captured shell command (including a heredoc)
   embedded verbatim, spanning multiple physical lines. A naive `grep -c '^[0-9]'` count
   of "one line = one record" is wrong for these two files specifically; Tier A (the
   canonical schema) does not have this problem because `oneline()` guarantees a single
   physical line per marker.
4. **`TOKENS`' `cost=` value is not strictly validated** (`gate-ledger.sh` sanitizes to
   `[0-9.]` only, so `1.2.3.4` is accepted, per the `advrun.log` sample above), display-only per the producer's own comment, never summed; a strict numeric parse of
   `cost=` will fail on malformed-but-accepted values and must degrade gracefully
   (treat as opaque string), not throw. **Exception:** a `TOKENS` line carrying `phase=<P>`
   (rung-4 cost checkpoint, `lib/gate/redteam-gate.sh`) IS summed, by `kit_gates`' own
   `cost` column (`lib/stats/src/stats/adapters.py::read_kit_gates`), which FIFO-pairs it
   onto the matching `GATE` row the same way an `OUTCOME` bracket pairs onto `caught`/
   `start_ts`/`end_ts`; a malformed `cost=` on a phase-scoped line parses to `NULL` there
   (never a fabricated `0.0`), so it degrades gracefully in the SAME direction this edge
   case already documents, just structurally rather than as an opaque string.
